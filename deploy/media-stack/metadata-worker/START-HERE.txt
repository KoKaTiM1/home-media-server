HOME MEDIA METADATA WORKER - WINDOWS PACKAGE 0.1.0

THE LAN CONNECTION IS ACTIVE; FIRST WINDOWS BATCH VERIFIED.

The USB delivered this application to Windows. Assignments and results travel
over the LAN to the server. The first Windows batch completed: 67 metadata
records received and applied, about 16 results/minute. New batches are assigned
as useful missing/stale metadata becomes due; an empty queue is normal.

SETUP OR REINSTALL:
1. Copy the entire folder to a local Windows drive; keep all files together.
2. Start Docker Desktop in Linux container mode.
3. Run 01-INSTALL.cmd to load the included image, then 02-OFFLINE-DEMO.cmd.
4. Retrieve the private worker.json connection file from the existing server
   account using authenticated SCP/SFTP. Save it as config\config.local.json.
   The dedicated metadata token and pinned server certificate are already set.
5. Run 04-START.cmd. Use 05-STATUS.cmd and 06-LOGS.cmd to inspect progress.
   07-STOP.cmd preserves local state and unacknowledged metadata.

The current worker.ps1 corrects a first-start missing-container inspection
error. A copy is available in the server account home as worker.ps1; update
that launcher locally for future fresh starts. The Docker client image remains
0.1.0; this script correction does not require downloading another image.
A physical stop/restart check with the corrected launcher remains in issue #2.

Keep the PC awake while working. After Windows reboot, start Docker Desktop
and run 04-START.cmd again. Automatic Windows startup was not installed.
The server falls back when the PC is offline and its outstanding leases expire.
No Windows SSH server or incoming remote-control account is required.

Keep config\config.local.json and data private and off GitHub. Retain the data
folder to preserve worker identity and pending uploads. The worker uses its own
metadata token; do not use a Jellyfin key, torrent password or GitHub token.

This helper fetches title and episode metadata from Cinemeta. It does not
download video/artwork or verify playback. Existing server verification and
Jellyfin import rules decide which movies/episodes are available to watch.

See README.md, server/README.md and PROTOCOL.md for operation and recovery.
VALIDATION.txt records the completed checks and remaining physical PC check.
